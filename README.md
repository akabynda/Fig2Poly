# Fig2Poly / CurveForge

Проект для обучения и сравнения моделей instance segmentation, выделяющих
каждую видимую кривую графика отдельной маской.

Текущий эксперимент сравнивает три готовые модели без текстовых промптов:

- `YOLO26x-seg`;
- `MaskDINO R50`;
- `MaskDINO Swin-L`.

Все модели обучаются на одинаковых train/validation/test-разбиениях,
составленных из синтетических и подходящих публичных данных. Цвета используются
только для разнообразия данных, а не как обязательный фильтр предсказаний.

## Что считается правильной маской

Для каждой физической кривой хранится отдельная бинарная маска. Если на
изображении пять кривых, целевой результат — пять instance masks.

Разметка описывает только видимую часть линии:

- участок под непрозрачной легендой, текстом или другим объектом исключается;
- пунктир и разрывы остаются частями одного экземпляра кривой;
- в месте пересечения пиксель может принадлежать маскам нескольких кривых;
- после сильного crop пустые маски удаляются, а `curve_count` обновляется.

Главный источник instance-разметки — `curve_masks`. Сводная
`instance_masks` не сохраняет многозначность пересечений и не должна
использоваться как основная обучающая разметка.

## Быстрый запуск генератора

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e .
curveforge --count 10000 --output dataset --workers 8
```

Запуск без установки пакета:

```powershell
pip install -r requirements.txt
python -m curveforge --count 20 --output dataset_preview
```

Воспроизводимая конфигурация и продолжение прерванной генерации:

```powershell
python -m curveforge --write-default-config config.json
python -m curveforge --config config.json --count 100000 --output dataset --workers 8 --resume
```

`--resume` переиспользует проверенные готовые образцы и атомарно записывает
новые. Генератор остановится с ошибкой, если конфигурация, seed, количество
образцов или разбиение не совпадают с начатым набором.

## Формат синтетического датасета

```text
dataset/
  dataset.json
  generation_state.json
  train.jsonl
  val.jsonl
  test.jsonl
  images/{train,val,test}/00000000.jpg
  semantic_masks/{train,val,test}/00000000.png
  instance_masks/{train,val,test}/00000000.png
  curve_masks/{train,val,test}/00000000/curve_001.png
  curve_masks/{train,val,test}/00000000/curve_002.png
  metadata/{train,val,test}/00000000.json
```

- `curve_masks` — отдельный 8-bit PNG для каждой видимой кривой;
- `semantic_masks` — объединение всех кривых, фон `0`, кривая `255`;
- `instance_masks` — вспомогательная 16-bit ID-карта без поддержки наложений;
- `metadata` — семейство и параметры функции, стиль, цвет, bbox, площадь,
  `panel_id`, искажения и пути к индивидуальным маскам;
- JSONL-манифесты — канонический список образцов каждого split.

Результат детерминирован seed и не зависит от количества worker-процессов.

## Разнообразие синтетики

Генератор создаёт:

- от 0 до 10 кривых: полиномы, сплайны, синусоидальные смеси, гауссовы и
  лоренцевы пики, ступенчатые и затухающие сигналы;
- одинаковые, разные и сгруппированные цвета, grayscale и colorblind-палитры;
- близкие, параллельные, пересекающиеся и почти совпадающие кривые;
- сплошные, пунктирные и штрихпунктирные линии, маркеры и разную толщину;
- светлые, тёмные, бумажные и цветные фоны;
- открытые, закрытые, минимальные и отсутствующие оси, разные сетки и деления;
- заголовки, подписи, легенды, аннотации, водяные знаки и hard negatives;
- 2–6 независимых subplot на одном изображении с собственными `panel_id`;
- перекрытия, поворот, перспективу и агрессивный crop;
- blur, шум, изменение яркости и контраста, уменьшение разрешения, scanlines,
  sharpening и JPEG-артефакты.

## Подготовка данных

Публичные наборы скачиваются выборочно: сохраняются только изображения и
аннотации, пригодные для задачи выделения кривых. Затем синтетические и
публичные манифесты объединяются в канонический набор.

MaskDINO получает точные сжатые COCO RLE-маски, включая несвязные фрагменты
пунктира и видимые разрывы. Формат сегментации YOLO основан на полигонах и не
может точно представить один экземпляр из нескольких несвязных компонентов.
Конвертер вынужденно соединяет такие компоненты и записывает статистику потерь
в `yolo_conversion.json`. Это ограничение должно учитываться при сравнении.

## Обучение на сервере

Полный воспроизводимый Linux-процесс описан в
[`server/README.md`](server/README.md).

```bash
cp server/.env.example server/.env
bash server/check_server.sh
bash server/setup_yolo.sh
bash server/setup_maskdino.sh

bash server/generate_synthetic.sh
bash server/download_public.sh
bash server/convert_public.sh
bash server/prepare_training_data.sh

bash server/train_yolo26x_seg.sh
bash server/train_maskdino_r50.sh
bash server/train_maskdino_swinl.sh
```

Окружения YOLO и MaskDINO изолированы. Обучающие скрипты автоматически
продолжают существующие запуски с `last.pt` или Detectron2
`last_checkpoint`. Для длительного запуска рекомендуется отдельная `tmux`
сессия на каждую модель.

Перед полным обучением обязателен smoke test на небольшом наборе, включающем
пустые графики. CUDA-операторы MaskDINO собираются непосредственно на целевом
сервере.

## Оценка

```bash
bash server/evaluate_all.sh
bash server/status.sh
```

Базовое сравнение проводится на одном нетронутом test split:

- COCO Mask AP, AP50 и AP75;
- centerline F1 с допусками в пикселях;
- симметричное расстояние между центральными линиями;
- точность количества кривых и count MAE;
- CHART-Info Task 6a на совместимом публичном benchmark;
- скорость инференса, пиковая VRAM и число параметров.

Confidence threshold и остальные выбираемые параметры фиксируются только по
validation split. Test split не используется для настройки. Метрики каждой
модели считаются как по её непосредственному выходу, без цветовых или
геометрических фильтров, чтобы сравнение архитектур оставалось однозначным.

Task 6b требует восстановления координат осей и масштаба. До появления
отдельного модуля калибровки её можно считать только с истинными параметрами
осей и обязательно помечать как `oracle-axis`, не смешивая с end-to-end
результатами из статей.
